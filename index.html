Introduction
What is the React Compiler?

A build-time plugin that reads your JSX, analyses data-flow, and emits optimised JavaScript with automatic memoization.

Build-time · Babel/SWC pluginRuns during your build, not in the browser. Zero runtime overhead for the analysis itself. Stable v1.0 — October 2025.
Automatic memoizationReplaces useMemo, useCallback, and React.memo — but more precisely. It traces actual data-flow, not your mental model.
React 17+ compatibleWorks with React 17, 18, and 19 via react-compiler-runtime. In production at Meta on Instagram and Quest Store.
~45 internal passes · 7 key stagesThis deck covers the 7 conceptual stages that explain what gets memoized and why.

InlineImmediatelyInvokedFnInlines IIFE patterns directly into surrounding code.
MergeConsecutiveBlocksCombines adjacent basic blocks that don't branch — simplifies the control-flow graph.
SSAStatic Single Assignment — each variable assignment gets a unique name for full traceability.
EliminateRedundantPhiRemoves Phi nodes whose inputs are all the same value — pointless merges.

PruneUnusedLabelsRemoves basic-block labels never targeted by a jump.

FlattenReactiveLoopsLoops cannot have independent scopes per iteration — flattens them.

Type Inference
+ Effect Analysis

Classify each value's type. Annotate every instruction with what happens to that value — its effect. Together they decide what's safe to cache.

Types you'll seeTObject (plain obj), TFunction, TPrimitive (number/string), TObject<BuiltInJsx> (React element), TObject<BuiltInProps> (props from React).
Create

New value — mutable.
Mutate

MutateTransitive

Via alias/closure.
Capture

Stored in closure.
Read

Read-only — safe.

Limitations
When the compiler skips

Skips gracefully — original code unchanged, no errors — when it can't guarantee safety.

❌ Conditional hooks
function MyComponent({ shouldFetch }) { if (shouldFetch) { const data = useQuery("/api/data"); } // hook in conditional → skip }
❌ Hooks in loops
function TodoList({ items }) { return items.map(item => { const [done] = useState(false); // useState inside .map return <TodoItem key={item.id} />; }); }
❌ Class components
// class components not supported class MyComponent extends React.Component { render() { return <div>{this.props.data}</div>; } }
❌ Global state mutations
let globalCounter = 0; function Counter() { globalCounter++; // Mutate on global → unsafe return <div>{globalCounter}</div>; }
❌ Direct DOM manipulation
function MyComponent() { document.title = 'New Title'; // side effect in render return <div>...</div>; }
✅ Already perfectly memoized
// compiler rebuilds it more precisely const filteredData = useMemo( () => data.filter( item => item.category === filter), [data, filter] );
Safe fallback + opt outWhen skipped, original code is emitted unchanged. Use 'use no memo' at the top of a function to explicitly opt out.

React 19 · Hook 1 of 6
use() new

Unwrap promises and context directly inside render. Unlike all other hooks — it can be called conditionally.

ReplacesThe useEffect + state boilerplate pattern for reading async data. Write const data = use(promise) and Suspense handles loading.
Conditional callsuse(Context) can be called after early returns, inside conditionals, inside loops. useContext() cannot.
Server → ClientServer component creates a promise and passes it as a prop. Client unwraps with use() — data fetching starts immediately, no waterfall.
With compilerThe use() call itself is not memoized. Values derived from the resolved data are automatically wrapped in cache guards.
use() — promises and context
import { use } from 'react'; // ── 1. Unwrap a promise ────────────────── function OrderList({ ordersPromise }) { const orders = use(ordersPromise); return <ul>{orders.map(o => <li>{o.id}</li>)}</ul>; } // wrap in Suspense — no useEffect/useState needed <Suspense fallback={<Spinner/>}> <OrderList ordersPromise={fetchOrders()}/> </Suspense> // ── 2. Context after early return ─────── function ThemeButton({ show }) { if (!show) return null; // early return OK const theme = use(ThemeContext); // after early return OK return <button style={theme}>Click</button>; } // useContext() would throw here // ── 3. Server → Client ─────────────────── async function Page() { const promise = fetchOrders(); // starts immediately return <OrderList ordersPromise={promise}/>; }
React 19 · Hook 2 of 6
useOptimistic() new

Show an optimistic UI state immediately while an async action is in flight. Reverts automatically if the action fails.

What it replacesTwo state variables + manual revert logic on error. One hook now handles the full pattern.
APIconst [optimistic, addOptimistic] = useOptimistic(state, updateFn)
The updateFn merges the optimistic update into current state.
Automatic revertWhen the parent transition resolves (success or error), optimistic state is replaced by actual server state. You never manage rollback.
Works with useTransitionWrap your server action in startTransition. Optimistic update shows during the transition. React knows when to sync.
useOptimistic() — instant feedback, auto-revert
import { useOptimistic, useTransition } from 'react'; function OrderList({ orders, onMarkShipped }) { const [isPending, startTransition] = useTransition(); const [optimisticOrders, addOptimisticOrder] = useOptimistic( orders, (currentOrders, shippedId) => // update fn currentOrders.map(o => o.id === shippedId ? {...o, status:'shipped'} : o ) ); const handleShip = (orderId) => { startTransition(async () => { addOptimisticOrder(orderId); // instant UI await onMarkShipped(orderId); // server call // success → orders updates from server // error → reverts automatically }); }; return ( <ul>{optimisticOrders.map(o => ( <li key={o.id}>{o.status} // shows 'shipped' immediately <button onClick={() => handleShip(o.id)}>Ship</button> </li> ))}</ul> ); }
React 19 · Hook 3 of 6
useActionState() new

Manage loading, error, and result state from form actions in a single hook.

What it replaces3 separate state variables for pending / error / result. One hook, one source of truth.
APIconst [state, action, isPending] = useActionState(fn, initialState)
Action function receives previous state as first arg — easy to accumulate results.
Progressive enhancementPass action to <form action={action}>. Works without JavaScript. React hydrates the result server-side.
Error handling built inReturn an error from your action function. No try/catch at the component level needed.
useActionState() — form state in one hook
import { useActionState } from 'react'; async function createOrderAction(prevState, formData) { const item = formData.get('item'); try { const order = await createOrder({ item }); return { success: true, order, error: null }; } catch (e) { return { success: false, order: null, error: e.message }; } } function CreateOrderForm() { const [state, action, isPending] = useActionState(createOrderAction, { success: false, order: null, error: null, }); return ( <form action={action}> <input name="item" disabled={isPending}/> <button disabled={isPending}> {isPending ? 'Creating...' : 'Create Order'} </button> {state.error && <p>{state.error}</p>} {state.success && <p>Order #{state.order.id} created!</p>} </form> ); }
React 19 · Hook 4 of 6
useFormStatus() new

Read the submission state of a parent form from any child component — no prop drilling.

What it solvesA submit button deep inside a form needs to know if the form is submitting. Previously: pass isPending through every layer. Now: child reads it directly.
APIImport from 'react-dom' (not 'react'). Must be called inside a component rendered inside a <form>. The form must use the action prop.
data fieldContains the FormData being submitted — useful for showing which values are in-flight or building optimistic UI based on inputs.
PatternExtract your submit button into its own component. Use useFormStatus() inside it. Parent form stays clean, button is self-contained.
useFormStatus() — no prop drilling
import { useFormStatus } from 'react-dom'; // note: react-dom // self-contained — reads form state itself function SubmitButton({ label = 'Submit' }) { const { pending, data } = useFormStatus(); const submittingItem = data?.get('item'); return ( <button type="submit" disabled={pending}> {pending ? `Creating "${submittingItem}"...` : label} </button> ); } // parent form — clean, no isPending prop passed down function CreateOrderForm({ action }) { return ( <form action={action}> <input name="item" placeholder="Order item"/> <SubmitButton label="Create Order"/> // no isPending </form> ); } // ⚠ rules: // 1. import from 'react-dom', not 'react' // 2. component must render inside a <form> // 3. form must use action prop, not onSubmit
React 19 · Hook 5 of 6
useTransition() enhanced

Now accepts async functions. isPending stays true for the entire async operation — including every await.

What changed in React 19React 18: startTransition only accepted sync functions. React 19: async is fully supported. isPending covers the entire async lifecycle.
Low-priority renderingTransitions tell React: this is not urgent. If the user types during a transition, React interrupts it and handles the input first.
Error handlingIf the async function throws, React catches it and shows the nearest Error Boundary. No try/catch needed inside startTransition.
With useOptimisticCall addOptimistic() inside startTransition. Optimistic update shows instantly, transition runs the async work, reverts on failure.
useTransition() — async support in React 19
import { useTransition, useOptimistic } from 'react'; function Dashboard({ orders }) { const [isPending, startTransition] = useTransition(); const [optimistic, addOptimistic] = useOptimistic( orders, (cur, id) => cur.filter(o => o.id !== id) ); const handleDelete = (orderId) => { startTransition(async () => { // async — new in React 19 addOptimistic(orderId); // instant UI await deleteOrder(orderId); // isPending stays true here // React syncs server state when done }); // isPending → false here }; // React 18: startTransition(() => {}) — sync only // React 19: startTransition(async () => {}) — async OK if (isPending) return <p>Updating...</p>; return <ul>{optimistic.map(o => ( <li key={o.id}>{o.id} <button onClick={() => handleDelete(o.id)}>✕</button> </li> ))}</ul>; }
React 19 · Hook 6 of 6
useDeferredValue() enhanced

Now accepts an initialValue parameter — show a placeholder on first render instead of blocking.

What changed in React 19React 18: no deferral on first render. React 19: useDeferredValue(value, initialValue) shows initialValue on first render, component suspends, then renders with real value.
Without initialValueFirst render: deferred = current value (no deferral). Useful for keeping stale results visible while new results load — but no skeleton on first load.
With initialValueFirst render: deferred = initialValue. React suspends → shows Suspense fallback → renders with real deferred value. Perfect for skeleton screens.
vs useTransitionuseTransition: you control when the update starts. useDeferredValue: React automatically defers expensive subtrees that receive the value as a prop.
useDeferredValue() — initialValue in React 19
import { useDeferredValue, Suspense } from 'react'; // React 18 — no initialValue function SearchResults18({ query }) { const deferred = useDeferredValue(query); // first render: deferred === query (no deferral) return <Results query={deferred}/>; } // React 19 — with initialValue function SearchResults19({ query }) { const deferred = useDeferredValue(query, ''); // first render: deferred === '' (initialValue) // React suspends → shows Suspense fallback // then renders with real deferred value return <Results query={deferred}/>; } // shows skeleton on first load function SearchPage({ query }) { return ( <Suspense fallback={<ResultsSkeleton/>}> <SearchResults19 query={query}/> </Suspense> ); } // with compiler: Results is automatically memoized — // re-renders only when deferred value changes
